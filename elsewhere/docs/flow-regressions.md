# Personal-flow regression checks

Use separate browser storage for testing (for example, `127.0.0.1` instead of an existing `localhost` session). Example visits are persistent local data.

1. **Filtered lists:** Save SLOMA, search for pottery, and open Want to try. The empty state explains that filters hide saved entries. Clear filters restores SLOMA and keeps Want to try open. Repeat after choosing another city or filtering a different map area.
2. **Favorites:** With no visit history, Favorites has no results even when interests match the catalog. After loading example visits, only the three liked visits appear. Disliked and okay reactions must not qualify.
3. **Activity map:** Enable Favorites, choose Los Angeles, then open Emma’s guide and SLOMA. Tap Map. The city becomes San Luis Obispo, the activity marker and card are present, and the map centers on the venue. Distance labels still refer to Downtown SLO; the venue center must not be treated as device location.
4. **Example guide notes:** Emma’s guide displays a recommendation under all four picks. Preview contains the same notes.
5. **Social toggle:** Disable Example social data. Discover has no sample guide or social score selectors, Activity and the Guides Explore tab show empty states, and My guide remains available. Repeat after a reload and when disabling examples from Emma’s guide.
6. **Guide preservation:** Load example visits, open Guides → My guide → Create my guide, select Edit guide, move Leaning Pine above SLOMA, and add a guide note. Return to Guides → My guide and reopen the collection. Order and notes remain intact, including after a reload. Unit tests additionally cover intentionally emptied guides and excluding disliked, okay, and unresolved visits from initial generation.
7. **Visit editing:** Open a scored activity and choose Edit under Your visit. Change its note and revisit choice, then save without comparisons. The score, rank, saved-list membership, and guide order remain unchanged. Reload to confirm persistence. Preview the guide and confirm the private visit note is absent.

The browser checks above accompany the core tests; physical iOS/Android checks are still needed for native map positioning, keyboard behavior, and location permissions.

8. **Guide library:** Both Guides navigation entries open the library. All four example covers open their matching titles and place counts. Search narrows the grid; an unmatched search shows an empty state. Save all updates each bookmark. Map markers and the share preview use only the selected guide. Back from a place returns to its guide. My guide stays selected when returning from the personal guide.

9. **Onboarding:** On a fresh test origin, the welcome heading and six unchecked interests appear together. Select Creative and Relax, reload, and confirm both remain selected. Continue to Discover: all 11 results remain available, matching interests sort first, and example social scores are off. On another fresh origin, Skip for now and continuing with no selections both show the general catalog. Setup never requests location permission.
10. **First save:** The Discover list shows a dismissible saving tip. Save an experience, confirm Saved to Want to try, and use View list to see it. Reload, return to Discover, and unsave: neither onboarding nor the tip returns. On a fresh completed setup, dismiss the tip without saving and confirm dismissal survives reload. Saving from details or Guide Save all also retires the tip.
11. **Storage and accessibility:** Core tests cover valid legacy histories (including empty lists), interrupted drafts, corrupt records, write ordering, and retry. In the browser, interest checkboxes must expose checked states and work with the keyboard. Check 320px-wide layout, larger text, reduced motion, and native back/restart behavior. A load failure must present a retry screen without overwriting storage; a save failure must show a retry action.

12. **Activity picker:** The center + opens a searchable activity picker regardless of the current city, list, or discovery filters. Selecting an activity opens its visit form. My Lists has no guide-creation promotion or example-guide card; guide creation remains under Guides → My guide.
